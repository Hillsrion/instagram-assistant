# Evaluation Module Documentation

The `eval/` module provides a comprehensive pipeline to evaluate the quality of the RAG system (see [RAG_PIPELINE.md](RAG_PIPELINE.md) for an overview of the pipeline). It clearly distinguishes two aspects:

1. **Retrieval** (`eval_retrieval.py`): Tests if the correct chunks are retrieved
2. **Generation** (`eval_generation.py`): Tests the quality of answers generated by LLMs

## Quick Start

```bash
# 1. Generate an evaluation dataset (50 QA pairs)
python -m eval.dataset.generate_dataset 50

# 2. Evaluate RETRIEVAL quality
python -m eval.retrieval.eval_retrieval

# 3. Evaluate GENERATION quality (compare LLMs)
python -m eval.generation.eval_generation qwen3:latest mistral --trials 10 --html

# 4. Compare different RAG configurations
python -m eval.config_comparison.compare_configs

# 5. Generate a multi-model dashboard (aggregates all JSON reports)
python -m eval.generation.model_dashboard

# 6. Validate enrichment quality
python -m eval.enrichment.validate_enrichment --sample --size 20
```

## Evaluation Dataset

### Location
The dataset is stored in `eval/eval_dataset.json` (ignored by git).

### Versioned Sample
A sample file `eval/eval_dataset.sample.json` is versioned with dummy data to:
- Serve as a reference for the expected format
- Allow pipeline testing without real data
- Document the structure of QA pairs

To use the sample:
```bash
cp eval/eval_dataset.sample.json eval/eval_dataset.json
python -m eval.eval_retrieval
```

### Dataset Format
```json
{
  "metadata": {
    "total_pairs": 50,
    "by_type": {"factual": 17, "summary": 17, "implicit": 16},
    "by_difficulty": {"easy": 15, "medium": 25, "hard": 10}
  },
  "qa_pairs": [
    {
      "question": "Natural language question?",
      "expected_answer": "Expected answer based on the source chunk",
      "source_chunk_ids": ["conversation_chunk_001"],
      "question_type": "factual",
      "difficulty": "easy",
      "metadata": {
        "participants": ["Alice", "Bob"],
        "date_range": "2024-03-15 - 2024-03-15"
      },
      "tags": []
    }
  ]
}
```

> **Note**: `source_chunk_ids` is a list allowing reference to multiple source chunks
> for a single question (e.g., questions requiring information from multiple conversations).
> The old format `source_chunk_id` (singular) is still accepted in reading for backward compatibility.

## CLI Scripts

### 1. Dataset Generation (`dataset/generate_dataset.py`)

Generates synthetic question-answer pairs from indexed chunks.

```bash
python -m eval.dataset.generate_dataset 50
python -m eval.dataset.generate_dataset --samples 100
```

**Types of questions generated:**
- **Factual**: Direct information extraction
- **Summary**: Synthesis questions
- **Implicit**: Questions requiring inference

---

### 2. Retrieval Evaluation (`retrieval/eval_retrieval.py`)

**Objective**: Test if the RAG system retrieves the correct source chunks.

```bash
# Basic syntax
python -m eval.retrieval.eval_retrieval

# With filters
python -m eval.retrieval.eval_retrieval --question-type factual,summary
python -m eval.retrieval.eval_retrieval --difficulty easy,medium
python -m eval.retrieval.eval_retrieval --participant "Alice"

# With custom judge model
python -m eval.retrieval.eval_retrieval --judge qwen3:latest
```

**Calculated Metrics:**

| Metric | Description |
|--------|-------------|
| **Hit@k** | % of questions where at least one correct chunk is in the top-k results |
| **MRR** | Mean Reciprocal Rank - ranking quality |
| **Recall@k** | Fraction of source chunks retrieved in the top-k |
| **Precision@k** | Fraction of top-k results that are source chunks |
| **Faithfulness** | Faithfulness of the answer to sources (LLM-as-judge, without expected answer bias) |
| **Relevance** | Relevance of the answer to the question (LLM-as-judge) |
| **Conciseness** | Conciseness of the answer (LLM-as-judge) |

**Output:**
```
=== Benchmark Report: default ===
Total questions: 50

Retrieval Metrics:
  Accuracy (Hit@k): 84.0%
  MRR: 0.762
  Avg Rank: 1.45

Generation Metrics:
  Faithfulness: 78.5%
  Relevance: 82.3%

By Question Type:
  factual: Acc=92.0%, Faith=85.0%
  summary: Acc=76.0%, Faith=72.0%
  implicit: Acc=84.0%, Faith=78.0%
```

### 3. Generation Evaluation (`generation/eval_generation.py`)

**Objective**: Compare the generation quality of different LLMs, independently of retrieval.

The script directly provides the source chunk to each LLM, thus isolating generation quality from retrieval quality.

```bash
# Syntax
python -m eval.generation.eval_generation <model1> <model2> [options]

# Examples
python -m eval.generation.eval_generation qwen3:latest mistral
python -m eval.generation.eval_generation qwen3:latest qwen2.5:3b --trials 10
python -m eval.generation.eval_generation mistral neural-chat --trials 20 --html
python -m eval.generation.eval_generation --models qwen3:latest,mistral --judge qwen3:latest
```

**Options:**

| Option | Description | Default |
|--------|-------------|---------|
| `models` | Models to compare (min. 2) | `qwen3:latest qwen2.5:3b` |
| `--trials` | Number of questions to test | 3 |
| `--html` | Generate an HTML report in addition to JSON | false |
| `--judge` | Judge model for evaluation | config.llm_model |

**Calculated Metrics:**

| Metric | Description |
|--------|-------------|
| **Faithfulness** | Is the answer faithful to the provided sources? |
| **Relevance** | Does the answer respond well to the question? |
| **Speed** | Generation speed (words/second) |

**Generated Reports:**

A JSON report is always generated in `eval/results/eval_generation/`:
- Name: `gen_<trials>trials_<model1>_vs_<model2>_<timestamp>.json`
- Contains metrics, summary, and details per question

With `--html`, an interactive HTML report is also generated:
- Name: `gen_<trials>trials_<model1>_vs_<model2>_<timestamp>.html`
- Comparison charts
- Details per question with side-by-side answers
- Judge's observations
- Final summary

**Performance Optimization (2-Phase Evaluation):**
The script uses a **2-Phase Batch Strategy** to minimize VRAM usage and model loading time:
1. **Phase 1: Generation** — Loads each model sequentially and generates answers for *all* questions.
2. **Phase 2: Judgment** — Loads the Judge Model *once* and evaluates all generated answers in batch.
This approach prevents "VRAM ping-pong" (repeated loading/unloading) and is significantly faster for local execution.

### 4. Configuration Comparison (`config_comparison/compare_configs.py`)

Compares multiple RAG configurations on the same dataset (retrieval + generation).

```bash
python -m eval.config_comparison.compare_configs
python -m eval.config_comparison.compare_configs --question-type factual
```

**Configurations compared by default:**

| Config | Query Rewriting | Reranking | Hybrid Search | Context Expansion |
|--------|-----------------|-----------|---------------|-------------------|
| `full` | ✓ | ✓ | ✓ | ✓ |
| `no_reranking` | ✓ | ✗ | ✓ | ✓ |
| `no_hybrid` | ✓ | ✓ | ✗ | ✓ |
| `minimal` | ✗ | ✗ | ✗ | ✗ |

---

### 5. Multi-Model Dashboard (`generation/model_dashboard.py`)

**Objective**: Aggregate all JSON reports from `eval_generation` and produce an interactive HTML dashboard comparing models.

```bash
# Generation with default path
python -m eval.generation.model_dashboard

# Generation with custom path
python -m eval.generation.model_dashboard --output dashboard_report.html
```

The script scans `eval/results/eval_generation/*.json`, extracts metrics per model from each report, and generates an interactive HTML with:

- **Checkboxes** per model (checked by default) to dynamically filter
- **3 bar charts** (Faithfulness, Relevance, Speed) via Chart.js, updated in real-time
- **Detailed table** with averages and number of reports per model
- Stack: Tailwind CSS + Chart.js (consistent with other reports)

**Output:** `eval/results/eval_generation/dashboard_<timestamp>.html`

## Programmatic Usage

### Generate a Dataset

```python
from rag_pipeline.config import Config
from rag_pipeline.vector_store import VectorStore
from eval import SyntheticDataGenerator

config = Config()
vector_store = VectorStore(config)
vector_store.load()

generator = SyntheticDataGenerator(config)
qa_pairs = generator.generate_dataset(
    vector_store.chunks,
    target_size=50
)
generator.save_dataset(qa_pairs)
```

### Evaluate Retrieval

```python
from eval import BenchmarkRunner, BenchmarkConfig, SyntheticDataGenerator

config = Config()
generator = SyntheticDataGenerator(config)
qa_pairs = generator.load_dataset()

runner = BenchmarkRunner(config)
bench_config = BenchmarkConfig(
    name="custom",
    use_query_rewriting=True,
    use_reranking=True,
    use_hybrid=True,
    top_k=5
)

report = runner.run_benchmark(qa_pairs, bench_config)
print(report.summary())
```

### Use Metrics

```python
from eval import RAGASMetrics

metrics = RAGASMetrics(config)

# Faithfulness (without expected_answer to avoid judge bias)
score = metrics.compute_faithfulness(
    question="Who said hello?",
    generated_answer="Alice said hello",
    source_content="Alice: Hello!"
)

# Conciseness
score = metrics.compute_conciseness(
    question="Who said hello?",
    generated_answer="Alice said hello"
)

# Recall@k and Precision@k (support multiple source chunks)
recall = metrics.compute_recall_at_k(
    source_chunk_ids=["chunk_001", "chunk_002"],
    retrieved_results=results,
    top_k=5
)
precision = metrics.compute_precision_at_k(
    source_chunk_ids=["chunk_001"],
    retrieved_results=results,
    top_k=5
)

# Score with explanation (for reports)
result = metrics.compute_faithfulness_with_explanation(
    question="...",
    generated_answer="...",
    source_content="..."
)
# {"score": 0.85, "explanation": "The answer is faithful..."}
```

## Main Classes

### QAPair
```python
@dataclass
class QAPair:
    question: str                # The question
    expected_answer: str         # The expected answer
    source_chunk_ids: List[str]  # IDs of source chunks (multi-source)
    question_type: QuestionType  # factual, summary, implicit, temporal
    difficulty: Difficulty       # easy, medium, hard
    metadata: dict               # Metadata (participants, date_range)
    tags: List[str]              # Optional tags
```

### BenchmarkConfig
```python
@dataclass
class BenchmarkConfig:
    name: str
    use_query_rewriting: bool = True
    use_reranking: bool = True
    use_hybrid: bool = True
    use_context_expansion: bool = True
    top_k: int = 5
```
