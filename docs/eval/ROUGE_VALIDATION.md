# ROUGE-L Validation for Enrichment Summaries

Guide to using ROUGE-L (Recall-Oriented Understudy for Gisting Evaluation) for validating narrative summaries in enrichment.

## What is ROUGE-L?

**ROUGE-L** measures the **Longest Common Subsequence (LCS)** between two texts.

- **Input**: Two texts (reference and candidate)
- **Output**: Score 0.0-1.0 (1.0 = identical)
- **Calculation**: Measures longest matching word sequence in same order
- **Use case**: Compare generated summaries against ground truth

### Key Characteristics

✅ **Sequence-aware**: Rewards matching word order
✅ **Stemming**: Uses word stems ("recommend", "recommends" = same)
✅ **Symmetric**: Can compare any two texts
❌ **Not semantic**: Won't match synonyms ("recommend" ≠ "suggest")
❌ **Strict on order**: "A loves B" ≠ "B loves A"

## Quick Start

### Calculate ROUGE-L Score

```python
from eval.eval_enrichment import EnrichmentValidator

validator = EnrichmentValidator()

reference = "Alice recommends a new restaurant to Bob"
candidate = "Alice suggests a restaurant for Bob"

score = validator.calculate_rouge_l(reference, candidate)
print(f"ROUGE-L: {score:.2%}")  # Output: ROUGE-L: 50.00%
```

### Validate with Ground Truth

```python
from rag_pipeline.chunker import Chunk
from eval.eval_enrichment import EnrichmentValidator

chunk = Chunk(
    chunk_id="chunk_001",
    # ... other fields ...
    narrative_summary="Alice asks Bob about restaurant on Main Street",
    reference_summary="Alice inquires about a new restaurant on Main Street",  # Ground truth
)

validator = EnrichmentValidator()
report = validator.validate_chunk(chunk)

# Check ROUGE-L in metadata
summary_result = report.field_results["narrative_summary"]
if "rouge_l" in summary_result.metadata:
    rouge_score = summary_result.metadata["rouge_l"]
    print(f"ROUGE-L: {rouge_score:.2%}")
```

## Score Interpretation

| ROUGE-L Score | Interpretation | Action |
|---|---|---|
| **1.0 (100%)** | Perfect match | ✓ Excellent |
| **0.8-0.99** | Excellent similarity | ✓ Use as-is |
| **0.6-0.79** | Good match | ✓ Good quality |
| **0.4-0.59** | Fair match | ⚠️ Review |
| **0.2-0.39** | Poor match | ✗ Fix needed |
| **0.0-0.19** | Very poor match | ✗ Reject |

## Examples

### Perfect Match

```
Reference: "Alice recommends a new restaurant to Bob"
Candidate: "Alice recommends a new restaurant to Bob"
ROUGE-L:   100.00%
```

All words match exactly in same order.

### Same Meaning, Different Words

```
Reference: "Alice recommends a new restaurant to Bob"
Candidate: "Alice suggests a different place to eat with Bob"
ROUGE-L:   50.00%
```

LCS: "Alice" → "a" → "restaurant" → "to" → "Bob"
- Shared: 5 words
- Reference: 8 words
- Candidate: 8 words

### Partial Overlap

```
Reference: "Alice recommends a new restaurant to Bob on Main Street"
Candidate: "Alice suggests going to a restaurant downtown"
ROUGE-L:   35.29%
```

LCS: "Alice" → "a" → "restaurant"

### No Overlap

```
Reference: "Alice recommends a new restaurant to Bob"
Candidate: "The weather was nice today"
ROUGE-L:   0.00%
```

No common words in any order.

## Validation Integration

When a chunk has a `reference_summary`, the validator automatically:

1. **Calculates ROUGE-L** between generated and reference summary
2. **Stores score** in metadata: `field_result.metadata["rouge_l"]`
3. **Adjusts validation score** based on ROUGE-L:
   - ROUGE-L < 0.3 → score capped at 0.7 (warning: "Low ROUGE-L")
   - ROUGE-L < 0.5 → score capped at 0.85 (warning: "Moderate ROUGE-L")
   - ROUGE-L >= 0.5 → no penalty

## Working with Ground Truth

### Format

Add `reference_summary` field to chunks:

```python
chunk = Chunk(
    chunk_id="chunk_001",
    conversation_id="conv_001",
    # ... other required fields ...
    narrative_summary="Generated by LLM",
    reference_summary="Manually annotated ground truth",  # ADD THIS
)
```

### Creating Ground Truth Dataset

Minimal requirement: 50-100 chunks with reference summaries

```python
# Batch create ground truth
chunks_with_gt = []
for chunk in chunks[:100]:  # First 100 chunks
    # Manual annotation or careful review
    chunk.reference_summary = "Your ground truth summary here"
    chunks_with_gt.append(chunk)

# Validate
validator = EnrichmentValidator()
report = validator.validate_chunks(chunks_with_gt)

# Check ROUGE-L statistics
for chunk_report in report.chunk_reports:
    summary_result = chunk_report.field_results["narrative_summary"]
    if "rouge_l" in summary_result.metadata:
        print(f"{chunk_report.chunk_id}: {summary_result.metadata['rouge_l']:.2%}")
```

### Sources for Ground Truth

1. **Manual annotation** (most accurate)
   - Have 2-3 people independently write summaries
   - Use majority vote or consensus
   - Takes ~5-10 minutes per chunk

2. **Human review of LLM output** (fast but biased)
   - Read LLM-generated summary
   - Edit for accuracy/brevity
   - Use as ground truth

3. **Hybrid approach** (recommended)
   - LLM generates candidates
   - Human picks best or creates new
   - Faster than pure manual

## Comparing Models

```python
models = ["ministral-8b", "mixtral-8x7b", "llama2"]
results = {}

for model in models:
    enricher = ChunkEnricher(config, provider="ollama")
    enricher.model = model

    # Enrich sample chunks
    chunks = load_chunks_from_index(config, limit=50)
    for chunk in chunks:
        summary, ... = enricher.enrich_chunk(chunk)
        chunk.narrative_summary = summary

    # Validate
    validator = EnrichmentValidator()
    report = validator.validate_chunks(chunks)

    # Get ROUGE-L scores
    rouge_scores = []
    for chunk_report in report.chunk_reports:
        summary_result = chunk_report.field_results["narrative_summary"]
        if "rouge_l" in summary_result.metadata:
            rouge_scores.append(summary_result.metadata["rouge_l"])

    results[model] = {
        "avg_rouge_l": sum(rouge_scores) / len(rouge_scores) if rouge_scores else 0,
        "high_matches": sum(1 for s in rouge_scores if s > 0.6),
        "total_scored": len(rouge_scores)
    }

# Print comparison
print("Model Comparison (ROUGE-L):")
for model, stats in sorted(results.items(),
                           key=lambda x: x[1]["avg_rouge_l"],
                           reverse=True):
    print(f"{model:<20} Avg: {stats['avg_rouge_l']:.2%}  "
          f"High matches: {stats['high_matches']}/{stats['total_scored']}")
```

## Fallback: Word Overlap

If ROUGE-L is not available, use word overlap:

```python
validator = EnrichmentValidator()

reference = "Alice recommends restaurant"
candidate = "Alice suggests restaurant"

overlap = validator.calculate_word_overlap(reference, candidate)
print(f"Word Overlap: {overlap:.2%}")  # Jaccard similarity
```

**Word Overlap** (Jaccard similarity):
- `overlap = len(common_words) / len(all_unique_words)`
- Less strict than ROUGE-L
- Doesn't care about order
- Easier to pass but less informative

## Limitations & Workarounds

### Limitation 1: Doesn't Match Synonyms

```
Reference: "Alice recommends restaurant"
Candidate: "Alice suggests restaurant"
ROUGE-L:   50.00%  # Lower than expected!
```

**Workaround**: Use BERTScore for semantic similarity (not covered here)

### Limitation 2: Penalizes Paraphrasing

```
Reference: "Alice recommends a restaurant to Bob"
Candidate: "To Bob, Alice recommends a restaurant"
ROUGE-L:   70.00%  # Word order matters!
```

**Workaround**: Instruct LLM to maintain structure; accept lower ROUGE-L for paraphrases

### Limitation 3: Requires Ground Truth

```
# Without reference_summary, ROUGE-L is skipped
chunk.reference_summary = None  # No ROUGE-L calculation
```

**Workaround**: Create even small ground truth dataset (25-50 examples)

## Performance Benchmarks

Expected ROUGE-L scores by scenario:

| Scenario | Expected ROUGE-L | Notes |
|---|---|---|
| Human summary vs self | 0.95-1.00 | Identical |
| LLM vs human reference | 0.60-0.80 | Good quality |
| Poor LLM | 0.30-0.50 | Needs improvement |
| Very different | 0.00-0.20 | Completely wrong |

## Choosing Between Metrics

| Metric | Use When | Pros | Cons |
|---|---|---|---|
| **ROUGE-L** | Have ground truth | Sequence-aware, standard | Penalizes paraphrasing |
| **Word Overlap** | Quick assessment | Simple, fast | Ignores order |
| **BERTScore** | Need semantics | Understands meaning | Requires compute |
| **Manual review** | Quality matters | Most accurate | Time-consuming |
